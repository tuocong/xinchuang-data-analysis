# Linux 安全加固说明

> 适用系统：CentOS 7/8、openEuler、Rocky Linux  
> 加固目标：Web 服务器 + 数据库服务器的安全基线配置

---

## 一、SSH 加固

### 1.1 备份原配置
```bash
cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak.$(date +%Y%m%d)
```

### 1.2 修改 sshd_config
```bash
vi /etc/ssh/sshd_config
```

| 配置项 | 修改前 | 修改后 | 原因 |
|--------|--------|--------|------|
| `PermitRootLogin` | `yes` | `no` | 禁止 root 直接 SSH，防止暴力破解root密码 |
| `Port` | `22` | `2222` | 改默认端口，规避自动化端口扫描 |
| `PasswordAuthentication` | `yes` | `no` | 仅允许密钥登录（可选，更严格） |
| `MaxAuthTries` | `6` | `3` | 最多尝试 3 次密码 |
| `ClientAliveInterval` | `0` | `300` | 5分钟无操作自动断开空闲连接 |

### 1.3 重启 SSH 服务
```bash
systemctl restart sshd
# ⚠️ 不要关闭当前连接的终端！另开一个窗口测试能否登录
```

### 1.4 配置 fail2ban（防暴力破解）
```bash
yum install -y fail2ban

# 创建本地配置
cat > /etc/fail2ban/jail.local << 'EOF'
[DEFAULT]
bantime = 600          # 封禁 10 分钟
findtime = 300         # 5 分钟内的失败尝试
maxretry = 5           # 最多 5 次失败

[sshd]
enabled = true
port = 2222            # 改为你的 SSH 端口
logpath = /var/log/secure
EOF

systemctl enable fail2ban --now
fail2ban-client status sshd   # 查看封禁状态
```

## 二、防火墙规则（firewalld）

### 2.1 检查当前状态
```bash
firewall-cmd --state            # 确认防火墙已运行
firewall-cmd --list-all         # 查看当前开放端口和规则
```

### 2.2 配置白名单规则（最小权限原则）

```bash
# 默认区域设为 public
firewall-cmd --set-default-zone=public

# 只开放业务需要的端口
firewall-cmd --permanent --add-port=2222/tcp    # SSH（新端口）
firewall-cmd --permanent --add-port=80/tcp      # Nginx HTTP
firewall-cmd --permanent --add-port=443/tcp     # Nginx HTTPS
firewall-cmd --permanent --add-port=5000/tcp    # Flask API（内网）
firewall-cmd --permanent --add-port=9090/tcp    # Prometheus（内网）
firewall-cmd --permanent --add-port=3000/tcp    # Grafana（内网）

# 移除不需要的服务
firewall-cmd --permanent --remove-service=dhcpv6-client
firewall-cmd --permanent --remove-port=22/tcp   # 关闭默认 SSH 端口

firewall-cmd --reload                           # 重载生效
firewall-cmd --list-all                         # 验证
```

### 2.3 端口开放清单（生产环境参考）

| 端口 | 服务 | 开放范围 | 说明 |
|------|------|---------|------|
| 2222 | SSH | 仅办公网络 IP | 或通过 VPN 访问 |
| 80/443 | Nginx | 公网 | Web 入口 |
| 5000 | Flask API | 仅内网 | 后端服务不暴露公网 |
| 9090 | Prometheus | 仅内网 | 监控指标 |
| 3000 | Grafana | 仅内网 | 监控面板 |
| 3306 | MySQL | 仅 localhost | 数据库不对外 |

## 三、操作审计（rsyslog）

### 3.1 记录所有用户命令

```bash
# 创建审计脚本
cat > /etc/profile.d/audit.sh << 'EOF'
# 操作审计：记录所有用户执行的每条命令
export PROMPT_COMMAND='RETRN_VAL=$?;logger -p local6.debug "$(whoami) [PID:$$] FROM $(who -m | awk "{print \$NF}" 2>/dev/null || echo "local"): $(history 1 | sed "s/^[ ]*[0-9]\+[ ]*//") [exit:$RETRN_VAL]"'
EOF

source /etc/profile.d/audit.sh
```

### 3.2 配置 rsyslog 单独存储审计日志

```bash
cat > /etc/rsyslog.d/audit.conf << 'EOF'
# 将 local6.debug 的日志写入独立文件
local6.debug    /var/log/commands.log
& stop
EOF

systemctl restart rsyslog
```

### 3.3 配置日志轮转（防止磁盘写满）

```bash
cat > /etc/logrotate.d/commands << 'EOF'
/var/log/commands.log {
    daily
    rotate 30
    missingok
    notifempty
    compress
    delaycompress
    postrotate
        /bin/systemctl reload rsyslog > /dev/null 2>&1 || true
    endscript
}
EOF
```

## 四、其他安全加固项

### 4.1 系统资源限制
```bash
cat >> /etc/security/limits.conf << 'EOF'
*   soft   nofile   65535     # 最大打开文件数（高并发必须调大）
*   hard   nofile   65535
*   soft   nproc    65535     # 最大进程数
*   hard   nproc    65535
EOF
```

### 4.2 内核参数优化
```bash
cat >> /etc/sysctl.conf << 'EOF'
net.ipv4.tcp_syncookies = 1          # 防 SYN Flood 攻击
net.ipv4.ip_forward = 0              # 不转发（非路由场景）
net.ipv4.conf.all.accept_source_route = 0  # 不接收源路由包
EOF
sysctl -p
```

### 4.3 自动安全更新
```bash
yum install -y yum-cron
systemctl enable yum-cron --now      # 自动安装安全补丁
```

## 五、验证清单

加固完成后逐项检查：

- [ ] `ssh root@IP -p 2222` → 提示 `Permission denied`（禁止 root 登录成功）
- [ ] `ssh user@IP -p 2222` → 正常登录
- [ ] 故意输错密码 5 次 → `fail2ban-client status sshd` 能看到封禁 IP
- [ ] `firewall-cmd --list-all` → 只开放了预期的端口
- [ ] `tail -f /var/log/commands.log` → 能看到自己刚执行的命令
- [ ] `ulimit -n` → 输出 65535

## 六、面试常见问题

**Q: 服务器上线前要做哪些安全配置？**

A: 五件事——SSH 加固（禁 root + 改端口 + fail2ban）、防火墙白名单（最小权限）、操作审计（rsyslog 记命令）、资源限制（nofile/nproc）、内核参数（syncookies 防 SYN Flood）。

**Q: fail2ban 工作原理？**

A: 监控日志文件（如 /var/log/secure），匹配正则规则（如 "Failed password for"），达到阈值就调用 iptables/firewalld 封禁该 IP 一段时间。

**Q: 为什么要禁 root 登录？**

A: Linux 的 root 账户名是固定的，黑客不需要猜用户名，只需要试密码。禁 root 后，必须先猜用户名再猜密码，攻击难度成倍增加。配合 fail2ban 基本杜绝暴力破解。
