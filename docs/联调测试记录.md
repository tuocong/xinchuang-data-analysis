## 七、发现的问题与处理

### 问题 1：CSV 响应头 charset 重复（已修复）
- **现象**：`GET /api/export` 返回 `Content-Type: text/csv; charset=utf-8; charset=utf-8`，charset 出现两次。
- **原因**：Werkzeug 对 `text/*` 类型会自动追加 `charset=utf-8`，代码中又手工写了一次。
- **修复**：`mimetype="text/csv; charset=utf-8"` 改为 `mimetype="text/csv"`。
- **状态**：已修复，需重启 Flask 生效。

### 问题 2：用户表主键 ID 跳号（非缺陷）
- **现象**：`sys_user.user_id` 为 1、3、5，缺少 2、4。
- **原因**：InnoDB 自增主键**删除后不复用**（被删除的 2、4 号用户不重新分配），这是数据库为保持审计一致性而设计的正常行为。
- **处理**：无需修复，在论文数据字典中说明该机制。

### 问题 3：`/api/repos` 响应体积偏大（遗留优化项）
- **现象**：单次返回 2.6 MB / 12213 行。
- **影响**：局域网/本机可接受，公网部署或大数据量下有优化空间。
- **优化方向**：改为服务端分页（`LIMIT/OFFSET`）+ `WHERE ... LIKE` 关键字过滤，把搜索下沉到 SQL。

## 八、结论

1. 18 个 API 接口**全部联通**，前端大屏、分析页、管理页均能正确取数。
2. **三级权限模型**（公开 / 需登录 / 仅管理员）生效，401 / 403 拦截符合预期。
3. JWT 登录、密码加盐哈希、操作日志落库、CSV 导出等安全与审计能力**真实可用**。
4. 发现 1 个编码小缺陷（已修复）、1 个非缺陷现象（ID 跳号）、1 个遗留优化项（服务端分页）。
