# 论文 4.2 节 —— 系统界面实现（初稿）

> 项目：信创开源生态数据分析系统
> 用途：直接作为论文「4.2 系统功能实现 / 系统界面实现」的正文素材。每个界面配「界面说明 + 实现要点」两段文字，截图就位后替换 `[图 4-x 占位]` 即可。
> 界面总数：**14 个**（登录、数据大屏、工作台、5 个分析页、数据管理、用户管理、系统日志、个人中心）。
> 技术栈说明：前端为纯 HTML5 + CSS3 + 原生 JavaScript + Apache ECharts（无 Vue/React 框架）；后端 Flask + PyMySQL；认证基于 JWT；全部页面同源部署，由 Flask 统一托管。

---

## 4.2.1 界面总体设计

系统界面采用**统一暗色主题**与**设计令牌（Design Tokens）**方案，在每页 `:root` 中定义同一套颜色变量：页面底色 `--surface-page: #0d0d0d`、卡片底色 `--surface-1: #1a1a19`、主色 `--series-1: #3987e5`（蓝）、辅助色 `#d95926`（橙）、`#199e70`（绿）、`#c98500`（黄）。所有页面共用该色板，保证视觉风格一致。

页面分为三大类：

1. **数据可视化类**（数据大屏、项目排名、语言分布、趋势分析、组织对比、组织钻取、仓库对比、项目筛选分析）——以 ECharts 图表为主，直接调用公开分析接口取数；
2. **数据管理类**（数据管理、用户管理、系统日志）——以表格 + 分页 + 筛选为主，其中用户与日志为管理员专属；
3. **系统辅助类**（登录、工作台、个人中心）——负责认证入口、功能导航与个人信息维护。

前端通过 `js/auth.js` 中的 `authFetch()` 统一封装请求：自动在请求头附加 `Authorization: Bearer <token>`，当接口返回 401 时自动清除本地令牌并跳转登录页，实现了会话过期时的统一拦截。

## 4.2.2 登录界面（login.html）

**界面说明**：登录页是系统的认证入口，包含「用户名」「密码」两个输入框与登录按钮。用户输入凭据后，前端调用 `POST /api/login`，服务端校验通过后返回 JWT 令牌；前端将令牌、用户名、角色写入 `localStorage` 并跳转至工作台。密码错误、用户被禁用等异常场景由后端返回对应提示并弹窗展示。

**实现要点**：

- 后端使用 `werkzeug.security.check_password_hash()` 校验加盐哈希密码，避免明文存储；
- 登录成功时调用 `log_action()` 写入一条「登录」操作日志，记录用户名、IP 与时间；
- 前端登录成功后依次写入 `token` / `loginUser` / `loginRole` 三个键，供后续 `requireLogin()` 与 `authFetch()` 使用。

## 4.2.3 数据大屏（index.html）

**界面说明**：数据大屏是系统的主界面，顶部为标题「信创开源项目数据分析大屏」与四个概览数字卡片（仓库总数、Star 总数、平均 Star、组织数），下方按「项目排名 / 语言分布 / 月度趋势 / 组织对比」四个维度布局四张图表。整屏以暗色卡片承载，是系统对采集数据最直观的聚合展示。

**实现要点**：

- 顶部数字卡片来自 `GET /api/overview`，读取 `ads_overview` 最新一条快照；
- 四张图表依次使用 ECharts **柱状图**（`chartRanking`，Top 项目）、**饼图**（`chartLanguage`，语言占比）、**折线图**（`chartTrend`，Star 累计趋势）、**柱状图**（`chartOrg`，组织 Star 对比），分别调用 `/api/ranking`、`/api/language`、`/api/trend`、`/api/org-compare`；
- 图表统一采用暗色配色与 `legend`、`tooltip`、`grid` 组件，保证数据可读性。

`[图 4-2 数据大屏]`

## 4.2.4 工作台（dashboard.html）

**界面说明**：工作台是登录后的功能导航中枢，顶部导航栏显示当前用户与「退出登录」按钮，主体以卡片形式提供到「数据大屏」「数据管理」「项目排名」「组织对比」等各功能模块的快捷入口，并展示系统关键统计数据的概览摘要。

**实现要点**：

- 页面加载时读取 `localStorage` 中的登录用户信息并渲染到导航栏；
- 「退出登录」调用 `handleLogout()` 清除 `token` / `loginUser` / `loginRole` 后跳回登录页；
- 概览数据复用 `GET /api/overview`，与数据大屏保持同一数据口径。

`[图 4-3 工作台]`

## 4.2.5 项目排名（ranking.html）

**界面说明**：项目排名页以横向柱状图展示 Star 数排名 Top 20 的开源项目，横轴为 Star 数、纵轴为项目名称，鼠标悬停可查看所属组织、编程语言、Fork 数及 Star 增量等明细，直观反映信创开源生态中的头部项目。

**实现要点**：

- 数据源 `GET /api/ranking`，读取 `ads_project_ranking` 最新快照，按 `rank_num` 升序返回；
- 采用 ECharts 横向条形图，Y 轴类别为项目名，并启用 `dataZoom` 便于滚动查看完整榜单；
- Star 数值经 `toLocaleString()` 千分位格式化展示。

`[图 4-4 项目排名]`

## 4.2.6 语言分布（language.html）

**界面说明**：语言分布页以环形饼图展示信创开源项目中各编程语言的仓库数量占比，辅以语言对应的 Star 总量，帮助分析生态内主流技术栈构成。

**实现要点**：

- 数据源 `GET /api/language`，读取 `ads_language_dist` 最新快照；
- 采用 ECharts 环形图（`radius: ['40%','70%']`），中心区域可叠加语言总数文案；
- 图例按仓库数降序排列，突出 Python、Java、C 等主力语言占比。

## 4.2.7 趋势分析（trend.html）

**界面说明**：趋势分析页以「折线 + 柱状」混合图表展示信创开源项目随时间的演变，折线为累计 Star 数增长曲线，柱状为各月份新增仓库数、活跃仓库数与新增 Star 数，从多个口径刻画生态的活跃度与成长性。

**实现要点**：

- 数据源 `GET /api/trend`，读取 `ads_monthly_trend` 按月份升序返回；
- ECharts 双 Y 轴配置：左轴承载柱状系列（新增/活跃仓库数），右轴承载累计 Star 折线；
- 折线系列启用 `areaStyle` 渐变填充，形成面积图视觉效果。

## 4.2.8 组织对比（org-compare.html）

**界面说明**：组织对比页对 Apache、阿里巴巴、华为等 2000 余个开源组织按 Star 总量、仓库数、活跃率等指标进行横向对比，以横向柱状图呈现 Top 组织的综合影响力。

**实现要点**：

- 数据源 `GET /api/org-compare`，读取 `ads_org_compare` 最新快照并按 `total_stars` 降序；
- 支持切换「Star 总量 / 仓库数 / 活跃率」等度量指标，动态刷新柱状图；
- 数据量较大（约 2067 个组织），前端默认截取 Top 若干名展示。

## 4.2.9 组织钻取（org-drill.html）

**界面说明**：组织钻取页实现「组织 → 仓库明细」的下钻查询。用户点击某一组织后，页面调用仓库明细接口展开该组织下的全部仓库列表（含 Star、Fork、Watch、语言、平台等字段），实现从汇总指标到明细数据的逐级下钻。

**实现要点**：

- 组织列表来自 `GET /api/org-compare`，明细来自 `GET /api/org-repos?org=<组织名>`；
- 后端 `api_org_repos` 通过 `fact_repo_stats` 与 `dim_project` 关联查询，并按 Star 降序返回；
- 前端以「可展开表格」交互呈现，点击行切换展开/收起状态，体现数据仓库钻取能力。

`[图 4-8 组织钻取]`

## 4.2.10 仓库对比（compare.html）

**界面说明**：仓库对比页支持选择多个目标仓库进行横向对比，以**雷达图**综合呈现各仓库在 Star、Fork、Watch、Issue 等多维指标上的轮廓差异，并以饼图辅助展示对比项的整体构成。

**实现要点**：

- 数据源 `GET /api/repos`，前端在内存中按所选仓库名过滤；
- ECharts 雷达图（`radar`）以指标轴 + 多序列呈现多仓库能力画像；
- 饼图用于展示所选仓库合计指标的结构占比，两者联动刷新。

## 4.2.11 项目筛选分析（analysis.html）

**界面说明**：项目筛选分析页提供按组织、语言、平台等条件的组合筛选，筛选结果以「柱状图 + 饼图 + 折线图」联动展示：柱状图展示筛选后的项目 Star 分布，饼图展示语言构成，折线图展示数量趋势，支持对 1.2 万余条仓库明细进行多维度探索。

**实现要点**：

- 数据源 `GET /api/repos`，前端在内存中完成条件过滤与聚合；
- 三张图表共享同一份筛选后的数据源，任一条件变化即同步刷新全部图表；
- 柱状图（项目分布）+ 环形饼图（语言）+ 折线图（趋势）体现多维联动分析能力。

## 4.2.12 数据管理（data.html）

**界面说明**：数据管理页以表格形式展示全部开源仓库明细，字段包括仓库全名、组织、语言、Star、Fork、Watch、平台等；顶部工具栏提供关键字搜索（仓库名/组织/语言）与「导出数据」按钮，底部为分页控件，可切换每页条数。

**实现要点**：

- 数据源 `GET /api/repos`，返回 12213 条明细；前端 `applySearch()` 实现客户端关键字过滤与分页；
- 「导出数据」调用 `GET /api/export`，后端用 `csv` 模块生成 CSV 并以 BOM 头（`﻿`）返回，保证 Excel 打开中文不乱码；
- 平台字段以徽章样式区分 Gitee / GitHub，增强可读性。

`[图 4-11 数据管理]`

## 4.2.13 用户管理（users.html）

**界面说明**：用户管理页为管理员专属，以表格展示系统用户（ID、用户名、角色、状态、创建时间），支持「新增用户」「编辑角色/状态」「删除用户」三类操作，均通过模态框完成输入与确认。

**实现要点**：

- 后端实现 `/api/users` 的 GET/POST/PUT/DELETE 四类操作，均叠加 `@login_required` + `@admin_required` 双重装饰器实现「先登录、后鉴权」；
- 新增用户时后端调用 `generate_password_hash()` 生成加盐哈希存储，前端表单提供「角色（admin/user）」与「状态（启用/禁用）」选择；
- 后端做安全校验：禁止删除自己、禁止修改自己的角色、角色值仅允许 `admin`/`user`，用户名查重；
- 每次增删改均调用 `log_action()` 记录操作日志，实现用户管理全程可审计。

`[图 4-12 用户管理]`

## 4.2.14 系统日志（log.html）

**界面说明**：系统日志页为管理员专属，以表格展示登录、导出、新增用户、修改用户、删除用户、修改密码等操作记录，字段包括时间、用户、操作类型、操作详情与 IP 地址；顶部提供按操作类型筛选与关键字搜索。

**实现要点**：

- 数据源 `GET /api/logs`，后端 `ORDER BY log_id DESC LIMIT 200` 返回最近日志；
- 操作类型以不同颜色徽章区分（登录=蓝、导出=绿、删除=红、修改密码=紫等），一眼可辨；
- 前端按类型与关键字双重过滤，支持分页浏览。

`[图 4-13 系统日志]`

## 4.2.15 个人中心（profile.html）

**界面说明**：个人中心页展示当前用户的头像、用户名、角色与基本信息，并以四张统计卡片呈现「登录次数 / 我的导出 / 我的收藏 / 操作日志」四项个人数据；右侧表单支持「基本资料维护」与「修改密码」。

**实现要点**：

- 身份信息来自 `GET /api/me`，个人统计来自 `GET /api/my-stats`（后端统计 `sys_log` 中当前用户的登录、导出、日志条数）；
- 修改密码调用 `POST /api/change-password`，后端先校验原密码、再写入新密码哈希，并记录「修改密码」日志；
- 姓名/邮箱/手机等扩展资料暂存于 `localStorage`（`sys_user` 表未设计对应字段），体现前后端职责分离。
